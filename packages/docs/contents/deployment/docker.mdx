# Docker Deployment

Jacky's Photography builds to a static Vite SPA. A production Docker image only needs to serve the files generated in `apps/web/dist/`; it does not need a Node.js runtime, SSR server, or database.

Use Docker when you want to self-host the already-built gallery behind NGINX, Caddy, Traefik, or another reverse proxy. GitHub Pages and Cloudflare Pages remain simpler for the current repository workflow.

## Prerequisites

- Docker.
- Access to the repository contents needed for the build.
- Node.js 24 and pnpm 10.19.0 inside the build stage.
- Perl in the build stage, because `exiftool-vendored` checks for it.

The current `builder.config.ts` reads source photos from `./photos` and uses `https://photos3.jackyw.cn/photos/` for original image URLs. If you change `storage.baseUrl` or use `storage.distPath`, make sure the final static files can still reach the original images.

## Static NGINX Image

Create a `Dockerfile` at the repository root:

```dockerfile
FROM node:24-bookworm-slim AS builder

WORKDIR /app
RUN corepack enable

COPY . .

RUN apt-get update \
  && apt-get install -y --no-install-recommends perl \
  && rm -rf /var/lib/apt/lists/*

RUN pnpm install --frozen-lockfile
RUN pnpm run photos:standardize
RUN pnpm build

FROM nginx:1.27-alpine AS runtime

COPY deploy/nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=builder /app/apps/web/dist/ /usr/share/nginx/html/

EXPOSE 80
```

Create `deploy/nginx.conf`:

```nginx
server {
  listen 80;
  server_name _;
  root /usr/share/nginx/html;
  index index.html;

  location /assets/ {
    try_files $uri =404;
    add_header Cache-Control "public, max-age=31536000, immutable";
  }

  location /thumbnails/ {
    try_files $uri =404;
    add_header Cache-Control "public, max-age=31536000, immutable";
  }

  location / {
    try_files $uri $uri/ /index.html;
  }
}
```

Build and run:

```bash
docker build -t jackys-photography .
docker run --rm -p 8080:80 jackys-photography
```

The gallery will be available at `http://localhost:8080`.

## Image Contents

The runtime image contains only the static build output:

```plain
/usr/share/nginx/html/
```

That directory is copied from:

```plain
apps/web/dist/
```

The builder stage may read `photos/` to generate thumbnails and manifest data, but the final image should only contain photo originals if your storage configuration explicitly copies originals into the web build, such as through a local `distPath`.

## Configuration Notes

- Keep `config.json.url` aligned with the public URL served by your container or reverse proxy.
- Keep `builder.config.ts` aligned with where original photos are served from.
- `photos/incoming/` is excluded from the manifest by `excludeRegex`; run `pnpm run photos:standardize` before publishing new incoming files.
- If your container host serves behind a subpath, review Vite `base` handling before building.

## Verification

After the container starts, check:

- The homepage loads without 404s for `/assets/*` and `/thumbnails/*`.
- Deep routes fall back to `index.html`.
- Fullscreen viewer requests original image URLs successfully.
- `sitemap.xml`, `feed.xml`, and `site.webmanifest` are reachable if they are present in the build output.
